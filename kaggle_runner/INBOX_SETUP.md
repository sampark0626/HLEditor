# 아이폰 자동 처리 설정 가이드

경기가 끝나고 **아이폰에서 영상만 올리면**, Kaggle이 자동으로 하이라이트를 만들어 YouTube에 올리고
**알림으로 BAND 글을 보내 주는** 흐름을 설정합니다. 웹호스팅이나 서버는 필요 없습니다.

```
아이폰 Drive 앱 ─업로드→ Drive HLEditor/01_inbox
      ▲                         │ (Apps Script가 일·월 5분, 그 외 1시간마다 확인)
      │                         ▼
  ntfy 알림 ◀── Kaggle 커널(hleditor-inbox): 병합 → 오디오 → 팬∥Gemini → 빌드 → YouTube
  (탭하면 BAND 글 복사)
```

설계 배경은 저장소 루트의 [MOBILE_PLAN.md](../MOBILE_PLAN.md)에 있습니다.
처음 한 번 설정하는 데 **40분 정도** 걸립니다.

## 준비물

- HLEditor가 설치된 PC (YouTube 업로드에 쓰던 `client_secrets.json`이 있는 상태)
- Google 계정 (YouTube 채널이 있는 계정)
- Kaggle 계정 — **휴대폰 인증 완료**(인터넷을 쓰는 커널 실행에 필요, 지금 Kaggle 러너를 쓰고 있다면 이미 됨)
- 아이폰

---

## 1. Google Cloud Console (5분)

1. [console.cloud.google.com](https://console.cloud.google.com)에서 YouTube 업로드에 쓰는 **기존 프로젝트**를 고릅니다.
2. **API 및 서비스 → 라이브러리**에서 `Google Drive API`를 찾아 **사용**을 누릅니다.
3. **OAuth 동의 화면(대상)**에서 게시 상태를 확인합니다. **'테스트'면 [앱 게시]를 눌러 '프로덕션'으로** 바꿉니다.
   테스트 상태로 두면 7일마다 인증이 만료되어 자동 처리가 멈춥니다.
   개인용이라 Google 검수를 받을 필요는 없습니다. 로그인할 때 "확인되지 않은 앱" 화면만 한 번 거치면 됩니다.

## 2. PC에서 비밀값 만들기 (5분)

HLEditor 폴더에서 실행합니다.

```bash
py -3 tools/make_kaggle_secrets.py --kaggle-user <Kaggle 아이디>
```

- 브라우저가 열리면 YouTube 채널 계정으로 로그인하고 권한(Drive, YouTube)에 동의합니다.
  "확인되지 않은 앱"이 나오면 **고급 → (안전하지 않음)으로 이동**을 누릅니다.
- 내 드라이브에 `HLEditor/` 폴더와 하위 폴더(01_inbox … _state)가 자동으로 생깁니다.
- `kaggle_secrets/` 폴더에 파일 3개가 생깁니다. **절대 공유하거나 커밋하지 마세요**(.gitignore 등록됨).
  - `hl_secrets.json`: Kaggle에 올릴 비밀값
  - `apps_script_properties.txt`: Apps Script에 넣을 값
  - `dataset-metadata.json`: kaggle CLI로 올릴 때만 씀

## 3. Kaggle (10분)

1. **비공개 데이터셋 만들기**
   - kaggle.com → Datasets → **New Dataset** → `hl_secrets.json` 업로드
   - 제목은 `hl-secrets`로 하고, **Private(비공개)**인지 꼭 확인한 뒤 Create를 누릅니다.
   - 주소가 `kaggle.com/datasets/<아이디>/hl-secrets` 인지 확인합니다.
2. **API 토큰 만들기**
   - kaggle.com → 오른쪽 위 프로필 → **Settings → API**에서 새 토큰을 만듭니다.
   - `KGAT_`로 시작하는 새 토큰을 권장합니다. 예전 방식(`kaggle.json` 안의 `key` 값)도 동작합니다.
3. 커널(노트북)은 따로 만들 필요 없습니다. 첫 자동 실행 때 `hleditor-inbox`라는 이름으로 생깁니다.

> 비밀값을 Kaggle Secrets가 아니라 비공개 데이터셋에 두는 이유: API로 실행한 커널에서는
> Kaggle Secrets를 읽을 수 없습니다(Kaggle/kaggle-cli issue #582).

## 4. Apps Script (10분)

1. [script.google.com](https://script.google.com) → **새 프로젝트**를 만들고 이름을 `HLEditor 트리거`로 바꿉니다.
2. 편집기의 `Code.gs` 내용을 모두 지우고, 저장소의 `kaggle_runner/apps_script/Code.gs` 내용을 붙여넣은 뒤 저장합니다.
3. 왼쪽 **⚙ 프로젝트 설정 → 스크립트 속성**에 `apps_script_properties.txt`의 값을 한 줄씩 넣습니다.
   `KAGGLE_API_TOKEN`에는 3단계에서 만든 토큰을 넣습니다.
4. 편집기 위쪽 함수 목록에서 **`installTrigger`**를 고르고 **실행**을 누릅니다. 권한 승인 창이 뜨면 허용합니다.
   "확인되지 않은 앱"이 나오면 **고급 → (안전하지 않음)으로 이동**을 누릅니다(내가 만든 스크립트라 정상).
   이제 5분마다 확인이 돌아갑니다(일·월요일 외에는 1시간에 한 번만 실제로 확인합니다).
5. 함수 목록에서 **`showStatus`**를 실행합니다. 실행 로그에 `Kaggle 커널 상태: IDLE`이 나오면 Kaggle 연결은 정상입니다.
   처음엔 커널이 없어서 IDLE이 맞습니다. 오류가 나면 `KAGGLE_USERNAME`과 `KAGGLE_API_TOKEN`을 확인합니다.
6. 함수 목록에서 **`testPush`**를 실행합니다. 영상 없이 Kaggle 커널을 한 번 돌려 보는 시험입니다.
   2~5분 뒤 kaggle.com → Code → **hleditor-inbox** → 최신 버전의 로그 끝에 `끝 — 경기 0개`가 보이면
   GitHub 코드 받기, 비밀값 데이터셋, Google 인증, Drive 폴더까지 모두 정상입니다.

## 5. 아이폰 (5분)

1. **ntfy** 앱(App Store)을 설치하고 **+ → 주제(topic)**에 `apps_script_properties.txt`의 `NTFY_TOPIC` 값을 넣어 구독한 뒤 알림을 허용합니다.
2. **Google Drive** 앱 → 설정에서 **Wi-Fi에서만 파일 전송을 끄고** 모바일 데이터로도 올릴 수 있게 합니다.
3. Drive 앱에서 `HLEditor/01_inbox` 폴더에 **별표**를 해 두면 찾기 쉽습니다.

## 6. 첫 시험 (20~30분)

1. 5분 이상인 짧은 경기 영상을 Drive 앱으로 `01_inbox`에 올립니다(아래 '평소 사용법' 참고).
2. 일·월요일이면 5분 안에 Kaggle이 시작됩니다(알림은 오지 않습니다 — 아래 '평소 사용법' 3번 참고).
   다른 요일이면 Apps Script에서 `tick`을 직접 실행하면 됩니다. 시작됐는지는 Apps Script **실행(Executions)** 기록이나
   kaggle.com → Code → `hleditor-inbox`에서 볼 수 있습니다.
3. 20~30분 뒤 마지막 영상까지 처리하고 나서 약 20분을 더 기다린 다음, **"하이라이트 1경기 완료 (영상 1개 처리)"** 알림이 한 통 오면 확인합니다.
   - ntfy 앱에서 메시지를 탭하면 BAND 글 전체가 복사되는지
   - YouTube 영상에 제목(`2026-12-06-1경기` — `날짜-경기번호`)·슈팅 장면 타임스탬프·썸네일·우상단 워터마크가 들어갔는지
   - Drive의 원본이 `03_done`으로 옮겨졌는지
   - 완료 알림에 **"압축된 것 같습니다"** 경고가 없는지. 있으면 폰에서 화질이 낮아진 채 올라간 것이니, 올리는 방법을 바꿔야 합니다.
4. 문제가 있으면 Kaggle → Code → `hleditor-inbox` → 최신 버전의 **Log**를 확인합니다.

**첫 시험에서 같이 확인하면 좋은 것 (설계 가정)**
- 로그의 `받음:` 줄에 나오는 영상 길이
- 30분이 넘는 경기를 올렸다면, 두 파일이 한 경기로 합쳐졌는지(`나뉜 파일 2개를 한 경기로 합쳤습니다`)
- YouTube 공개 범위가 원하는 대로인지(기본은 PC의 `.env` 설정. 바꾸려면 `hl_secrets.json`의 `YOUTUBE_PRIVACY`를 고치고 데이터셋 새 버전 업로드)

## 평소 사용법

1. 경기가 끝나면 **Drive 앱 → `HLEditor/01_inbox` → + → 업로드 → 사진 및 동영상**에서 영상을 고릅니다.
   - XbotGo 앱의 영상은 먼저 사진 앱에 저장해 둡니다.
   - **30분 단위로 나뉜 파일은 한 번에 같이 고릅니다.** 자동으로 한 경기로 합쳐집니다.
   - 사파리로 올리지 마세요. 사진 보관함의 영상을 720p로 압축해서 올립니다.
2. 업로드가 끝날 때까지 **Drive 앱을 켜 둡니다**(5G로 경기당 4~10분). 다른 앱으로 가면 업로드가 멈출 수 있습니다.
3. 올린 영상을 **모두 처리한 뒤 알림이 딱 한 통** 옵니다. 영상을 여러 개 올려도, 업로드가 오래 걸려도 마찬가지입니다.
   - 처리는 첫 영상이 올라오면 바로 시작해 업로드와 나란히 진행하지만, 알림은 보내지 않습니다.
   - 인박스가 비어도 마지막 영상을 끝낸 뒤 **20분(`LINGER_MIN`)** 동안 더 올라올 영상을 기다린 다음 알립니다.
     그래서 마지막 영상을 올린 뒤 알림까지 경기당 20~30분에 20분이 더 걸립니다.
   - 제목의 **"(영상 N개 처리)"** 로 올린 영상이 몇 개 처리됐는지 확인합니다. 올린 개수와 같으면 다 끝난 것이니 다시 올리지 마세요.
4. 알림을 탭하고 ntfy 앱에서 **메시지를 탭하면 복사**됩니다. BAND에 붙여넣으면 끝입니다.
   - 본문 앞쪽이 BAND 글(그날 올린 경기가 모두 들어 있음)이고, 뒤의 `※` 줄은 확인할 일(합친 파일, 압축 경고, 실패 등)이니 붙여넣기 전에 지웁니다.
   - 실패한 영상도 이 알림 안에 `※ 처리 실패 — …`로 같이 옵니다. 처리기가 아예 멈춘 경우만 별도 알림이 즉시 옵니다.

**2D(Dot Play)가 필요한 경기**는 `01_inbox` 대신 `01_inbox_2d`에 올립니다. 2D 결과는 Drive `05_output`에 올라가고,
그 링크가 같은 알림의 `※` 줄에 들어갑니다. GPU로 실행되어 Kaggle 주간 GPU 한도를 쓰며, 마지막 영상 뒤 대기(`LINGER_MIN`)도 GPU 시간입니다.

## 폴더

| 폴더 | 뜻 |
|---|---|
| `01_inbox` | 여기에 올리면 자동 처리 |
| `01_inbox_2d` | 2D 변환까지 원하는 경기 |
| `02_processing` | 처리 중(건드리지 마세요) |
| `03_done` | 처리가 끝난 원본. 7일 뒤 휴지통으로 옮겨지고, 휴지통은 Drive가 30일 뒤에 비웁니다. 이름은 `2026-12-06-1경기_원본.mp4`(나뉜 파일은 `_원본1`, `_원본2`)로 바뀝니다 |
| `04_failed` | 실패한 원본. **`01_inbox`로 옮기면 다시 처리**합니다 |
| `05_output` | 2D 결과(`2026-12-06-1경기-2D.mp4`), YouTube 업로드에 실패했을 때의 하이라이트 백업(`2026-12-06-1경기.mp4`) |
| `06_clips` | 경기 하이라이트를 이루는 클립(`2026-12-06-1경기_c001.mp4` …). `HL_CLIPS`를 켠 뒤에만 쌓입니다. 월간 영상의 재료 — MONTHLY_PLAN.md |
| `07_monthly` | 월간 영상 `2026-12-월간.mp4`. **지우지 않습니다**(YouTube에서는 다시 받을 수 없어 Drive가 원본). 같은 달을 다시 만들면 옛 파일만 휴지통으로 갑니다 |
| `_state` | 처리 기록(날짜별 게시 목록, 판별 결과, `clips_*`·`games_*`). 지우지 마세요 |

## 문제 해결

| 증상 | 할 일 |
|---|---|
| 알림이 전혀 안 옴 | Apps Script → **실행(Executions)** 기록 확인. `showStatus` 실행 → Kaggle `hleditor-inbox` 로그 확인 |
| "Google 인증 만료" 알림 | PC에서 `py -3 tools/make_kaggle_secrets.py` 재실행 → Kaggle `hl-secrets` 데이터셋에 **New Version**으로 `hl_secrets.json` 업로드. ntfy topic은 그대로 유지됩니다 |
| "Kaggle 자동 실행 중지" 알림 | Kaggle 로그로 원인을 고친 뒤 Apps Script에서 `resetBreaker` 실행 |
| "처리 실패" 알림 | 알림에 적힌 이유 확인. 원본은 `04_failed`에 있음 → `01_inbox`로 옮기면 재시도 |
| "다음 파트가 오지 않아…" | 나뉜 파일 중 일부만 올라간 상태로 40분이 지남. 나머지를 올리면 따로 처리되니, 합쳐야 하면 PC 앱으로 처리 |
| 알림의 "(영상 N개 처리)"가 올린 개수보다 적음 | 나머지는 아직 올라오는 중이거나 마지막 대기(20분)가 끝난 뒤에 올라온 것. **다시 올리지 말고** 다음 알림을 기다리세요(그날 경기가 모두 든 새 알림이 옵니다). 업로드가 자주 20분 넘게 끊기면 `LINGER_MIN`을 늘리세요 |
| 공휴일 등 다른 요일 경기 | 스크립트 속성 `FAST_DAYS`에 그 요일 번호를 잠깐 추가(1=월 … 7=일). 또는 아래 실행 링크 사용 |
| Drive 저장공간 부족 | 무료 15GB는 한 경기일 분량(최대 약 15GB)도 빠듯함 → Google One 100GB 또는 `RETENTION_DAYS`를 줄이기 |

## 선택 기능

**실행 링크(지금 바로 확인):** Apps Script → 배포 → 새 배포 → 유형 '웹 앱'
→ 실행 계정 '나', 액세스 권한 '모든 사용자' → 배포 → URL 복사.
`URL?key=<KICK_KEY>` 를 폰 홈 화면에 추가하면, 누를 때마다 요일과 상관없이 바로 확인합니다.

**단축어 자동화(업로드 끝나면 즉시 시작):** 단축어 앱 → 자동화 → + → **앱** → Google Drive
→ '닫힘' 선택 → **즉시 실행** → 동작 'URL 콘텐츠 가져오기'에 위 실행 링크를 넣고, '실행 시 알림'은 끕니다.
Drive 앱에서 나오는 순간 처리가 시작됩니다. 일·월에는 5분 확인과 2~3분 차이라 없어도 됩니다.

**"처리 시작" 알림 (기본 꺼짐):** Apps Script 스크립트 속성에 `NOTIFY_START` = `1`을 추가하면 Kaggle을 시작할 때
"영상 N개 확인 — 처리 시작" 알림도 옵니다. 영상을 올리는 도중에 오면 다 올라간 줄 알고 헷갈리기 쉬워서 꺼 두었습니다.

## 설정값 (`hl_secrets.json`에 추가 가능 — 고친 뒤 데이터셋 새 버전 업로드)

| 키 | 기본값 | 뜻 |
|---|---|---|
| `DEFAULT_TITLE` | PC `.env`의 값 | 워터마크·YouTube 제목 앞부분 |
| `YOUTUBE_PRIVACY` | PC `.env`의 값 | `public` / `unlisted` / `private` |
| `SENSITIVITY` | `normal` | 후보 검출 민감도: `more` / `normal` / `strict` |
| `QUALITY` | `balanced` | 인코딩: `size` / `balanced` / `quality` |
| `RETENTION_DAYS` | `7` | `03_done` 원본 보관 일수 |
| `WAIT_NEXT_PART_MIN` | `40` | 나뉜 파일의 다음 파트를 기다리는 시간(분) |
| `SETTLE_SEC` | `180` | 마지막 파일이 도착하고 처리를 시작하기까지 기다리는 시간(초) |
| `LINGER_MIN` | `20` | 인박스가 빈 뒤에도 새 영상이 더 올라오는지 기다리는 시간(분). 다 기다린 뒤에 알림을 한 통 보낸다. `0`이면 기다리지 않고 바로 알림 |
| `MIN_GAME_SEC` | `300` | 이보다 짧은 영상은 처리하지 않음(실수로 올린 영상 보호) |
| `HL_REVIEW` | 꺼짐 | `"1"`이면 **검토 후 게시**: 분석만 하고 YouTube에는 안 올린 채 클립을 `06_clips`에 남기고, 폰에서 태깅·게시를 누르면(또는 다음 날 09:00에 자동으로) 올립니다. 아래 "검토 후 게시" 설치를 끝낸 뒤에만 켜세요. 클립 보관은 자동으로 함께 켜집니다 |
| `REVIEW_URL` | 없음 | 검토 페이지 웹 앱 주소("접근: 나만" 배포). "검토 준비" 알림을 누르면 이 주소가 열립니다. 없으면 알림이 와도 눌러서 열 수 없습니다 |
| `HL_CLIPS` | 꺼짐 | `"1"`이면 하이라이트를 이루는 클립을 Drive `06_clips`에 남기고 `_state`에 `clips_*.json`·`games_*.json`을 만듭니다(경기당 약 250MB, 월 약 3GB — MONTHLY_PLAN.md 3-7). 실패해도 게시는 그대로이고 알림에 `※ … 클립 보관 실패` 줄만 붙습니다 |

## 검토 후 게시 (선택 — 폰에서 상대팀·청백전 태깅)

기본 흐름은 "올리면 바로 YouTube까지"입니다. 이 기능을 켜면 **분석까지만 자동으로 하고, 폰에서 청백전/상대팀을
태깅한 뒤 게시**합니다(MONTHLY_PLAN.md). 검토하지 않아도 **경기 다음 날 오전 9시에 전체 장면으로 자동 게시**되므로
BAND 글이 막히지는 않습니다.

흐름: 영상 업로드 → 분석 → **"하루 하이라이트 검토 준비" 알림**(탭하면 검토 페이지) → 태깅 → **게시** →
BAND 글 알림(지금처럼 탭해서 복사). 검토 페이지에서 할 일:

- **경기 종류**: 청백전, 또는 다른 팀 + 상대 이름(최근 상대는 버튼으로 뜸). 게시 이름은 `2026-12-06-1경기-상대`.
- **장면마다**: 다른 팀 경기는 **공격/수비**를 고르고, 수비 장면 중 골을 먹은 장면에 **실점**을 누릅니다(월간 영상에서만 빠짐).
  AI가 잘못 잡은 장면에는 **잘못 잡힘**(주간·월간 모두에서 빠짐). **상대 득점 장면은 주간 영상에 그대로 남습니다.**
- 장면 제목을 누르면 그 클립이 재생됩니다(Drive 미리보기. 안 되면 `Drive에서 열기`).
- 이미 올라간(자동 게시된) 경기도 나중에 태깅하면 YouTube 제목이 바뀌고(영상은 다시 올리지 않음) 월간 영상에 반영됩니다.

설치(최초 1회, 약 15분):

1. Apps Script 프로젝트에 새 `Code.gs` 내용을 **덮어쓰고**, 파일 추가(+) → **HTML** → 이름 `Review` → `kaggle_runner/apps_script/Review.html` 내용을 붙여넣습니다.
   (브라우저 편집기에서 Ctrl+V가 막히면 MOBILE_PLAN.md 실행 로그 2026-10-11의 붙여넣기 요령을 따릅니다.)
2. 프로젝트 설정 → **시간대가 `Asia/Seoul`** 인지 확인합니다.
3. 배포 → **새 배포** → 유형 '웹 앱' → 실행 계정 **나**, 액세스 권한 **나만** → 배포. 이 주소가 검토 페이지입니다.
   (기존 실행 링크 배포는 '모든 사용자'로 그대로 두세요 — 검토 페이지는 소유자만 열립니다.)
4. 스크립트 속성에 `REVIEW_URL` = 3번의 주소를 추가합니다.
5. 편집기에서 `installDailyTrigger` 함수를 **한 번 실행**합니다(매일 09:00 자동 게시 트리거).
6. 아이폰 사파리로 검토 페이지 주소를 열어 **홈 화면에 추가**합니다(로그인은 한 번).
7. `hl_secrets.json`에 `"HL_REVIEW": "1"`과 `"REVIEW_URL": "<3번의 주소>"`를 추가하고 Kaggle 데이터셋 `hl-secrets`에 **새 버전**으로 올립니다.

끄는 법: `hl_secrets.json`에서 `HL_REVIEW`를 지우고 새 버전을 올리면 다음 실행부터 예전처럼 바로 게시합니다
(검토 대기 중이던 경기는 09:00 자동 게시되거나 검토 페이지에서 게시하면 됩니다).

| 증상 | 할 일 |
|---|---|
| "게시 실패" | 검토 페이지의 그 경기에서 **다시 게시**. YouTube 인증 문제면 알림의 안내(`make_kaggle_secrets.py` 재실행)를 따릅니다 |
| 검토 페이지가 "거부됨" | '나만'으로 배포한 주소인지, 같은 Google 계정으로 로그인했는지 확인 |
| 태깅했는데 월간에 안 들어감 | 월간에는 **경기 종류를 태깅한 경기**의 한울타리 장면만 들어갑니다. 다른 팀 경기는 장면마다 공격/수비가 정해져야 하고(실점·잘못 잡힘은 제외), 클립이 이미 정리됐으면 못 넣습니다. 월간 화면의 경기 목록에서 "월간 대상 n개"를 확인하세요 |
| 클립이 사라짐 | `06_clips`는 월간이 끝난 뒤 7일(늦어도 경기일 + 75일)에 휴지통으로 갑니다 — 아래 "월간 하이라이트". 수동으로 지우면 그 경기는 게시도 월간도 못 합니다 |

## 월간 하이라이트 (선택 — 검토 후 게시를 켠 경우)

태깅한 경기에서 **한울타리 장면만** 모아 한 달에 한 편, 약 6분 영상을 자동으로 만듭니다. 별도 설정은 없고,
위 "검토 후 게시" 설치(Apps Script 갱신·`installDailyTrigger`)와 `HL_REVIEW`만 있으면 됩니다.
Apps Script 코드를 새로 붙여넣은 뒤에 동작하므로 **Phase 3 배포 때 `Code.gs`와 `Review.html`을 다시 덮어써야 합니다.**

- **언제**: 매달 **1일 오전 9시**에 지난달 것을 만듭니다(첫 월간은 12월분 → 1/1). 태깅 안 된 경기(경기 종류가 없는 경기)가
  있으면 먼저 **"태깅 안 된 경기 n개"** 알림이 옵니다(누르면 월간 화면). 모두 태깅하면 **그 순간 바로** 만들고,
  3일 뒤 한 번 더 알리며, **7일이 지나면 태깅 안 된 경기를 빼고** 만듭니다.
- **무엇을**: 청백전 장면 전부 + 다른 팀 경기의 **한울타리 공격과 수비**(실점·잘못 잡힘은 제외). 점수 순으로
  경기당 4개·경기일당 8개 이내, 6분이 찰 때까지 고르고 날짜순으로 이어 붙입니다. 시작 카드 → 경기일 카드(`11월 20일 · 1경기 청백전`) →
  장면들 → **"이 달의 함성 1위"**(고른 장면 중 함성이 가장 큰 장면을 한 번 더). YouTube 설명에 챕터(경기일 + 함성 1위)가 들어갑니다.
- **어디에**: Drive `07_monthly/2026-12-월간.mp4`에 **먼저** 올리고 YouTube(공개 범위는 `YOUTUBE_PRIVACY`)에 올립니다.
  YouTube가 실패해도 Drive에 있으니 알림의 Drive 링크로 받으면 됩니다. 알림은 BAND 글(탭하면 복사)로 오고, 뒤의 `※` 줄에
  **월간에서 빠진 경기와 이유**가 이름과 함께 나옵니다(태깅 안 함 / 장면마다 공격·수비를 안 정함 / 점수가 낮아 못 듦 / 클립이
  정리됐거나 파일을 못 찾음). 같은 실행에 새 경기 영상이 있으면 월간은 그 영상을 다 처리한 **뒤에** 만듭니다(경기 게시가 늦어지지 않게).
- **다시 만들기**: 월간 화면(검토 페이지 → 월간 영상 → 달 선택)에서 태깅을 고친 뒤 **월간 다시 만들기**. 같은 이름의 옛 Drive 파일은 휴지통으로 가고
  YouTube에는 새 영상이 올라갑니다(옛 영상은 직접 지우세요). 1일 자동 생성을 놓친 달도 여기서 **지금 만들기**로 만들 수 있습니다.
- **클립 정리**: 월간이 끝난 뒤 **7일**, 월간이 안 끝나도 경기일 + **75일**이 지나면 `06_clips`의 클립을
  **휴지통**으로 보냅니다(영구 삭제 아님, Drive가 30일 뒤 비움). 이 기간은 코드에 고정돼 있어 `hl_secrets.json`으로 바꿀 수 없습니다
  (Apps Script의 예고 알림과 같은 날짜를 계산해야 해서). 월간이 **끝나지 않은** 경기는 75일 상한 **7일 전**에 알림이 옵니다 —
  그 전에 태깅해 월간을 만드세요(월간이 끝난 경기는 끝난 뒤 7일에 정리되므로 따로 예고하지 않습니다).
  게시 전 경기의 클립과 만든 지 7일이 안 된 클립은 지우지 않고, 월간 영상(`07_monthly`)과 `_state` 기록은 지우지 않습니다.
  정리된 경기는 월간 화면에 "클립 정리됨"으로 표시되고 다시 만들어도 들어가지 않습니다.
- **실패하면**: 월간 화면에 사유가 보이고 `월간 다시 만들기`로 다시 시도합니다(죽은 실행은 자동으로 3번까지). 장면이 하나도 없으면 만들지 않고 알립니다.
- 설정값(`hl_secrets.json`, 선택): `MONTHLY_TARGET_MIN`(기본 6분), `MONTHLY_CRF`(기본 20). 클립 보관 기간은 설정으로 바꿀 수 없습니다.
- 월간 화면의 월 목록에는 이번 달과 지난 2달이 나옵니다(경기 수·태깅 안 된 수는 그달 전체 기준). 더 오래된 달은 목록에서 빠지지만
  `검토 페이지 주소?page=review&month=2026-09`처럼 열 수 있습니다.
- 용량: 월간 영상 약 400~500MB(월), 클립은 월 약 3GB가 쌓였다가 정리됩니다.

## PC에서 시험하기 (Drive·Kaggle 없이)

```bash
py -3 -m kaggle_runner.inbox_runner --local-inbox D:\hl_test --dry-run --no-vision --settle-sec 0 --once
```

`D:\hl_test\01_inbox`에 영상을 넣고 실행합니다. YouTube 업로드와 알림은 콘솔 출력으로 대신하고,
만든 하이라이트는 `05_output`에 남습니다. `--no-vision`을 빼면 Gemini 판별까지 합니다(비용 발생).
`--clips`를 붙이면 클립 보관(`HL_CLIPS`), `--review`를 붙이면 검토 모드(`HL_REVIEW`)를 시험합니다.
검토 모드는 분석 뒤 `_state/games_*.json`을 `publish`로 바꾸고 `_state/requests.json`에
`{"items": [{"type": "publish", "date": "YYYY-MM-DD"}]}`를 쓴 다음 같은 명령을 다시 실행하면 게시 단계가 돕니다.
월간 영상은 `_state/monthly_YYYY-MM.json`(`{"status": "build"}`)과 `{"type": "monthly", "month": "YYYY-MM"}` 요청을 쓰고 같은 명령을 실행하면
만들어져 `07_monthly`에 남습니다(`--dry-run`이라 YouTube에는 올리지 않음).
